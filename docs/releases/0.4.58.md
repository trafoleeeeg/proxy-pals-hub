# Umbra 0.4.58 — устранение блокировки настройки iframe

На установленном 0.4.57 журнал за 10 октября 2026, 06:39:25–06:39:30
(Asia/Barnaul) показал успешную настройку именованных workers, затем конфликт
`Emulation.setLocaleOverride` на iframe и 4008 мс ожидания `Runtime.evaluate`.
Закрытие запросила защита страницы; snapshot и outbox завершились успешно.
Это не зарегистрированное падение Chromium в данном запуске.

Причина воспроизведена на настоящем Windows-движке: второй iframe использует
renderer, в котором другой живой агент уже установил язык. LocaleController
отвергает второго владельца. Проверка через JavaScript ждёт main-world контекст,
но provisional iframe удерживается `waitForDebuggerOnStart` до завершения этой
же проверки. Возникает взаимная блокировка и штатная защитная остановка.

Исправление хранит только живые подтверждённые владельцы настройки, привязанные
к Electron Session и `Runtime.getIsolateId`. Успешная native-команда подтверждает
язык владельца. Только известный ответ `Another locale override is already in
effect` допускает использование подтверждения другого живого владельца того
же isolate с тем же языком. После detach, уничтожения окна или отказа защиты
подтверждения отзываются. Другой Session, isolate, язык и произвольные ошибки
протокола не допускаются. При отсутствии доказательства сохраняется проверка
объявленного unique context и защитная остановка при реальном отказе.

Защита и new-document script по-прежнему устанавливаются ДО возобновления
iframe; default/numeric evaluation и увеличенные таймауты не используются.
Isolate IDs, протокольные ответы и содержимое страниц в журнал не пишутся.

Контрольный нативный запуск до исправления воспроизвёл тот же конфликт и
4-секундную остановку. После исправления проходят повторные переходы между
двумя loopback-сайтами с активным iframe-владельцем, включая полный production
runtime. Первый inline-script каждого iframe проверяет язык, часовой пояс,
CPU и screen width. Именованные classic/module workers продолжают проходить.
Негативные тесты проверяют запрет чужого/устаревшего подтверждения.

Сборка и полный Windows-прогон выполняются в GitHub до публикации.
Движок, база и реальные cookies не изменяются. Рабочая Umbra принудительно
не закрывается. После обновления результат нужно подтвердить на том же
профиле: синтетическое воспроизведение не покрывает все возможные сайты.
