# Согласование отпечатка Windows с прокси: первый этап

После успешной проверки выходного IP настольный клиент делает необязательный
HTTPS-запрос к `ipapi.co` **через ту же временную прокси-сессию**. Сервис видит
выходной IP прокси, но не получает cookies профиля или учётные данные прокси.
Ответ принимается только при совпадении IP с результатом проверки соединения.
Если геосервис недоступен или вернул неподтверждённый ответ, проверка прокси
остаётся успешной, а часовой пояс считается неизвестным.

Подтверждённый пояс сохраняется вместе с последним проверенным IP. При смене IP
старый пояс очищается. Для нового профиля выбор уже проверенного прокси задаёт
этот пояс автоматически. У существующего профиля несовпадение показывается в
редакторе с кнопкой явного применения: без действия владельца его отпечаток
не меняется. Геолокация IP может ошибаться, а смена пояса действующего профиля
может повлиять на сессию сайта.

Это не эмуляция GPU, Canvas, аудио или сетевого TCP-стека. Обычный режим
Electron по-прежнему может раскрывать реальное оборудование машины; строгий
режим блокирует часть API и этим отличается от обычного Chrome. Пассивный
TCP-отпечаток мобильного прокси формируется на стороне прокси и не исправляется
JavaScript-подменой в клиенте. Гарантии нераспознаваемости здесь нет.

Следующий этап проверяет нативным Electron-тестом, что основной документ,
dedicated worker и сторонний iframe согласованы по Windows User-Agent,
Client Hints (если API доступен движку), языкам, часовому поясу и числу ядер.
Проверка также сопоставляет `navigator.doNotTrack` с HTTP-заголовком `DNT`:
настройка профиля не должна выдавать противоположные значения в JS и сети.
Нативные GPU/Canvas/audio в обычном режиме этим изменением не изолируются.

## SharedWorker и ServiceWorker

Ранее нативный тест обнаружил системный Electron User-Agent в SharedWorker.
Подключение через отладчик отдельной страницы не решало проблему: shared
workers были недоступны, а ServiceWorker зависал до готовности его runtime.

Настольный клиент теперь запускает браузерный процесс через небольшой
координатор с наследуемыми анонимными каналами `--remote-debugging-pipe`.
Сетевой порт отладки не открывается; renderer не получает доступ к каналу.
Sandbox, contextIsolation, прежние хранилища профилей, single-instance lock
и штатное сохранение перед выходом остаются в браузерном процессе.

Browser-level auto-attach устанавливается до открытия persistent sessions.
SharedWorker и ServiceWorker приостанавливаются до первой строки кода и
получают политику своего BrowserContext: UA/UA-CH, язык, часовой пояс,
число ядер и скрипт ограничений профиля. Неизвестный контекст не запускается
без явно назначенной политики. Основная панель разрешена отдельно.

Важная граница текущего Chromium: неожиданно остановленный уже установленный
ServiceWorker не всегда приостанавливается заново до выполнения кода.
Поэтому потеря его runtime или приватного канала **блокирует сеть и останавливает
профиль**, а не продолжает работу с неподтверждённой защитой. Пользователь
получает уведомление. Требуется явно открыть профиль снова. Это не обещание
прозрачного восстановления после любого сбоя и не гарантия отсутствия любых
утечек. В обычном режиме регистрации ServiceWorker сохраняются при штатном
закрытии; строгий режим, как прежде, очищает регистрации перед запуском.

Нативные тесты проверяют параметры с первой строки скрипта, classic/module
workers, два профиля одновременно, HTTP-заголовки, зимнее и летнее смещение
Date, повторное открытие профиля и полный перезапуск приложения. Отдельно
проверяются остановка при потере защиты, отсутствие влияния на второй профиль
и сохранность cookies, localStorage и CacheStorage. Тесты используют только
синтетические данные и loopback-сервер; результаты не являются измерениями
реального пользовательского профиля на BrowserLeaks.

GPU/Canvas/audio/шрифты этим изменением не эмулируются. Обновление веб-панели
само по себе не защищает workers старого настольного клиента: нужен новый
бинарный клиент с этой реализацией.

Миграция `20260929100000_proxy_geo_timezone.sql` добавляет только необязательное
поле. До её применения список прокси и проверка соединения используют прежнюю
схему, поэтому панель остаётся работоспособной; определённый пояс при этом
ещё не сохраняется между загрузками.
