# Canvas, Audio, GPU и шрифты: проверенные границы

## Исправление частичных подмен

Локальный аудит на закреплённом Windows-движке `screen4` обнаружил ошибки
в разрешённых исключениях строгого режима. Обычный режим эти подмены не применял.

| Проверка | До исправления | Решение |
| --- | --- | --- |
| Полный Canvas и вырезка тех же пикселей | Разные данные | Удалён частичный JS-шум |
| HTML Canvas и OffscreenCanvas | Разные данные | Нативные readbacks при разрешённом API |
| AudioBuffer getChannelData/copyFromChannel | Разные данные, неверный offset | Удалён частичный JS-шум |
| Хвост destination после copyFromChannel | Изменялся вне скопированного диапазона | Нативная семантика без порчи данных |
| WebGL renderer и реальный графический backend | Подменялись только две строки | Разрешённый API не заявляет фиктивный GPU |

Владелец явно согласовал удаление этих неполных подмен. Старые seeds и GPU-поля
сохраняются в профилях без миграции/перезаписи, но диагностика помечает их как
неподдерживаемые. Запреты строгого режима, точные origins исключений, прокси,
права доступа к устройствам, sandbox и изоляция сайтов не отключаются.

**Это исправление согласованности и целостности данных, не скрытие оборудования.**
Разрешённые GPU, Canvas, Audio и CSS-шрифты могут характеризовать реальный ПК.
Нет гарантии неотличимости от Chrome или невозможности связать два профиля.

## Воспроизводимый тест

```powershell
node desktop/engine/run-rendering-audit.cjs D:\umbra-engine\temp\screen4-archive-check\electron.exe
# Только отдельное исследование на loopback, не настройка приложения:
node desktop/engine/run-rendering-audit.cjs D:\umbra-engine\temp\screen4-archive-check\electron.exe --software-research
```

Одноразовые сессии, локальный HTTP-сервер, обычный режим и разрешённые исключения
строгого режима. Проверяются главный документ, настоящий сторонний OOPIF,
dedicated worker, вырезки Canvas, PNG encode/decode, OffscreenCanvas, повторное
чтение, AudioBuffer copy/offset/нетронутый хвост, нативность WebGL getter и
совпадение renderer между документом и worker. Проверяется отсутствие результата
перечисления шрифтов: Chromium может вернуть пустой массив вместо исключения.
Сырые GPU-имена, шрифтовые списки, пиксели и аудиоданные остаются в renderer;
наружу выдаются только логические результаты. Сессии удаляются после теста.

Локально после исправления fixture прошёл на обычном и программном backend;
полный desktop-набор на `screen4` с обязательными native/DPAPI проверками —
132/132, без пропусков. Обычный rendering fixture добавлен в Windows CI.

Различие sampleRate AudioContext по умолчанию и явно заданного 48000 Hz
OfflineAudioContext **не является ошибкой API**: они вправе отличаться.
Это диагностическое наблюдение, а не тест на анонимность аудиоустройства.
Наличие `FontFace(local(...))` отдельно показывает, что запрет перечисления
шрифтов не изолирует CSS font lookup. Визуальные/нагрузочные тесты на других
ПК, AudioWorklet, shared/service graphics workers и все image transfer пути
этим fixture не покрыты.

## Исследование программного GPU

По разрешению владельца проверен отдельный тестовый процесс с
`--use-gl=angle --use-angle=swiftshader`. Не использовались unsafe-флаги,
отключение sandbox или настоящие сайты. На данном Windows-ПК WebGL сообщил
программный renderer, а WebGPU не предоставил адаптер. Обычный процесс
предоставлял аппаратные WebGL и WebGPU. Шрифты и AudioContext от смены этого
драйвера не изолировались.

Это процессная настройка, не политика BrowserContext. Нельзя добавить её как
переключатель одного профиля в текущем общем browser/GPU-процессе и заявить,
что остальные профили не изменились. Для отдельного режима нужны отдельный
browser process и проверенный жизненный цикл сохранения/обновления/прокси.

Chromium описывает SwiftShader как тестовый путь и отдельно предупреждает
о риске JIT в GPU-процессе и недопустимости считать unsafe WebGL fallback
безопасным способом запуска непроверенных сайтов:
[Chromium SwiftShader documentation](https://chromium.googlesource.com/chromium/src/+/main/docs/gpu/swiftshader.md).
Эти флаги не добавлены ни в приложение, ни в настройки пользователя, ни в CI.
Программный renderer не имитирует произвольную NVIDIA/AMD и может быть заметен.

## Что остаётся до независимой от ПК среды

- GPU: backend и его реальное поведение, WebGL/WebGPU capabilities, codecs и
  readback, а не только имя renderer. Отдельно безопасность программного backend.
- Canvas: контролируемые rasterizer, цветовые преобразования, шрифты и все
  пути передачи изображений; одной правки getImageData недостаточно.
- Audio: реальные параметры обработки/resampling, устройство вывода, задержки,
  OfflineAudioContext и AudioWorklet. Одних случайных поправок samples недостаточно.
- Шрифты: изолированный набор разрешённых к распространению файлов и нативный
  lookup/fallback для DOM/CSS/Canvas/workers. Установленные Windows-шрифты нельзя
  просто скопировать в распространяемый пакет без проверки лицензий.
- Подтверждение на нескольких физических конфигурациях и после перезапусков.

Эта доработка не повышает версию приложения и не выпускает автообновление.
