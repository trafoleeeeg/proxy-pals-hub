# Усиление изоляции профилей после 0.4.26

## Поведение по умолчанию

WebGL/WebGPU, чтение Canvas (в том числе OffscreenCanvas), Web Audio,
queryLocalFonts, SharedWorker и ServiceWorker закрыты. Рисование Canvas 2D
не запрещено. Полоса в оболочке сообщает о блокировке. В меню ◈ пользователь
может разрешить эти API для **точного origin** текущего сайта: схема, хост,
порт. Сторонние фреймы, поддомены и другие профили разрешение не наследуют.
Разрешения теперь разделены: GPU/WebGL/WebGPU, чтение Canvas, Web Audio,
локальные шрифты через API и Shared/Service Workers. Включение только workers
не открывает GPU, Canvas и Audio. Ранее сохранённое общее исключение остаётся
полным разрешением до тех пор, пока пользователь его не изменит. Новый формат
настроек хранит выбранные категории отдельно; повреждённый формат запрещает всё.

Исключение явно ослабляет защиту: нативные GPU/аудио/Canvas и общие/служебные
workers могут раскрывать реальные характеристики. Прокси, WebRTC-политика,
sandbox, запреты USB/HID/serial, геолокации, камеры, микрофона, захвата экрана
и WebAuthn не отключаются. Нельзя обещать анонимность после включения исключения.

Разрешения зашифрованы ОС, привязаны к профилю и остаются на этом ПК. Сохранение
настройки закрывает профиль с обычным сохранением cookies/вкладок. Изменение
применяется при повторном открытии: это останавливает старые контексты,
сохранившие ссылки на разрешённые API. Повреждённая настройка означает отказ,
а не разрешение. Настройки из облака не могут ослабить эту политику.

Перед открытием сетевого доступа сбрасываются только регистрации ServiceWorker,
чтобы ранее запущенный worker не обходил отозванное разрешение. Это может
потребовать повторной регистрации push/offline-функций сайта. Cookies,
localStorage, IndexedDB и Cache Storage этим действием не очищаются.

## Закрытые пути раскрытия данных

- Navigator/Screen/MediaDevices/CredentialsContainer защищены на прототипах,
  а не только через свойства экземпляров.
- Dedicated workers и OOPIF настраиваются через CDP до выполнения кода сайта.
  Зависшая/потерянная защита блокирует сеть и запускает сохранение/закрытие профиля.
- Заголовки сессии согласованы с профилем также у workers и первых запросов
  фреймов. Неизвестные нативные UA Client Hints не пропускаются.
- Проверка соединения больше не создаёт прямую сессию для получения IP машины.
  DNS/ICE без настоящего теста обозначены как «не подтверждено». Ошибка проверки
  не превращается в успешное «утечек нет».
- Облачные настройки расширений не скачивают и не устанавливают код.
  Установленный каталог не подключается ко всем профилям. В меню расширений
  требуется отдельное локальное разрешение; отключение тоже закрывает профиль.
  Ранее установленные расширения нужно разрешить заново для нужных профилей.
  Явная загрузка/обновление из панели предупреждает о запросе вне прокси профиля
  и требует согласия. CRX-подпись пока не проверяется: установка доверяет выбору
  пользователя, а не гарантирует подлинность произвольного архива.
- Подтверждённый отзыв доступа/потеря lease останавливает профиль при следующем
  heartbeat/save. Обычная временная сетевая ошибка не приравнивается к отзыву.
  Неудача сохранения не разблокирует сеть и не удаляет локальные данные.
- CHIPS/partitioned cookies отклоняются до очистки cookie jar. Это ограничение
  поддержки, а не реализация CHIPS: partition key больше не теряется молча.
- Публикация установщика зависит от Linux-тестов и Windows-сборки, а Windows
  перед упаковкой выполняет native tests с обязательными sandbox и DPAPI.

## Остаточные ограничения

Обычный Electron не становится другим устройством после импорта cookies.
CSS-метрики шрифтов, часть media queries/DPI во фреймах, производительность,
системное сглаживание и другие нативные поверхности не изолированы полностью.
JS-защита обнаружима. Для более сильной границы нужны изменения Chromium
и/или отдельная ОС/виртуальная машина с контролируемыми шрифтами и устройствами.
Гарантий нераспознаваемости, обхода проверок сайтов и восстановления входа
по любому набору cookies нет. Сессии могут быть отозваны или привязаны к устройству.

Без назначенного прокси профиль по-прежнему использует прямое соединение.
Панель, авторизация и обновление приложения не являются трафиком профильной сессии.

## Проверки

Регрессии используют синтетические cookies, локальные HTTP/HTTPS/SOCKS endpoints,
изолированные каталоги и sandboxed Electron. Нет доступа к production-БД или
пользовательским профилям. Native privacy fixture проверяет основную страницу,
dedicated worker, отдельный процесс iframe, точечное исключение, его неприменение
к стороннему фрейму и изоляцию cookie/localStorage. Windows-suite отдельно проверяет
DPAPI-снимок и восстановление после полного перезапуска процесса.

```powershell
$env:UMBRA_REQUIRE_NATIVE = '1'
$env:UMBRA_REQUIRE_DPAPI = '1'
npm --prefix desktop test
```

Проверки не доказывают отсутствие всех возможных fingerprint-поверхностей.
