# Umbra 0.4.57 — исправление защиты именованных dedicated workers

В журнале 0.4.56 за 10 октября 2026, 06:13:35 (Asia/Barnaul) зафиксировано:
настройка dedicated worker `Runtime.evaluate` завершилась ошибкой через 4013 мс,
после чего закрытие инициировала защита страницы. Локальный snapshot и outbox
успешно завершились. Это защитная остановка, а не зафиксированное падение renderer.

Найден конкретный воспроизводимый дефект: трекер контекстов принимал контекст
без `auxData.isDefault` только с пустым `name`. В используемом Chromium
`WorkerThreadDebugger::ContextCreated` передаёт в `V8ContextInfo` пользовательское
`WorkerOptions.name`, без флага `isDefault`, который используется для страниц.
Именованный worker ошибочно отвергался; ожидание заканчивалось через 4 секунды,
и неизменённая fail-closed политика останавливала профиль.

## Исправление

- Тип дочернего target регистрируется из CDP `Target.attachedToTarget` до
  `Runtime.enable`. Контекст с непустым именем принимается только для подтверждённого
  dedicated worker и только с объявленной `uniqueId`.
- Для page/iframe/неизвестной сессии этот допуск не применяется. Явные isolated
  worlds отвергаются; выбор страницы остаётся привязан к frameId.
- Нельзя возвращаться к numeric/default context или использовать контекст
  отсоединённой сессии. Таймаут и остановка при реальной потере защиты сохранены.
- В существующий ограниченный журнал добавлены только тип контекста и булевы
  признаки: именованный, есть uniqueId, принят, default world. Сами имена,
  context IDs, URL, script source, cookies и токены не записываются.

## Проверка

Контрольный запуск на настоящем Windows-движке до исправления: один именованный
worker на синтетической странице воспроизводит `PAGE_GUARD_FAILED`.
После исправления проходят именованные classic и module workers с проверкой
профильных CPU, языка и часового пояса. Страница доступна только через локальный
loopback fixture; рабочие сайты, реальные cookies и профили не используются.

Негативные тесты сохраняют запреты для page/iframe, неизвестной сессии,
isolated world, отсутствующей uniqueId и отсоединённого target.
Полные проверки и сборка установщика выполняются в GitHub перед публикацией.

Движок, база, права и данные профилей не меняются. Рабочую Umbra принудительно
не закрываем. После обычного обновления требуется проверить тот же рабочий
профиль; исправление этого воспроизведения не является обещанием отсутствия
любых других причин закрытия.
