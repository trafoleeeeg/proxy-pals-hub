# Изоляция шрифтов — экспериментальный нативный режим

Пользователь согласовал отдельный фиксированный набор. Это не имитация
стандартного набора Windows. Обычный режим сохраняет системные шрифты.
Нативный режим прошёл локальные проверки. Владелец согласовал выпуск 0.4.32;
публикация требует отдельной проверки архива, Windows CI и упакованного клиента.

## Реализуемая граница

- Политика BrowserContext устанавливается до первого renderer и неизменяема.
- `await session.setUmbraFontIsolation(files)` обязателен до запуска страницы
  или worker: чтение и разбор выполняются в MayBlock ThreadPool, не в UI-потоке.
  Позднее завершение после создания renderer отклоняется, без подмены уже
  действующей политики. Запуск профиля при отказе должен прерываться клиентом.
- Байты набора читаются один раз, проверяются и передаются через read-only memory.
  Это не список разрешённых имён с последующим поиском на ПК.
- Подбор семейства, fallback и CSS `local()` используют один набор.
- Отсутствующий символ не разрешает запасной поиск в системных шрифтах.
- Web-fonts, загружаемые сайтом, разрешены: они не происходят с ПК.
- `queryLocalFonts` запрещён обработчиками разрешений клиента даже при старом
  исключении `fonts` для сайта. Включить это исключение в изоляции нельзя.
- Не устраняются зависимости растеризации от движка, ОС, GPU и сглаживания.
- PDF, печать, плагины и нативные диалоги требуют отдельной проверки.

## Два пути загрузки в Chromium 152 / Windows

`FontDataServiceAllWebContents` включён по умолчанию, но CSS `local()` использует
отдельный `DWriteFontProxy`. Поэтому для изолированной сессии регистрируется
свой FontDataService, локальный поиск переводится туда же, а устаревший IPC
отключается. Обычные сессии продолжают пользоваться исходными сервисами.

## Прототип набора

Arimo, Tinos, Cousine: Regular/Bold/Italic/BoldItalic. Исходные неизменённые
статические TTF из Chromium `third_party/test_fonts/test_fonts`. Это небольшой
набор, не полный набор Unicode; CJK/emoji могут отсутствовать. Текущая версия
прототипа явно отклоняет variable fonts и TTC, вместо частичной поддержки.

Источник архива закреплён в DEPS Chromium 152.0.7977.130:

- bucket `chromium-fonts`, объект `9c07d19d9c5ee1ff94f717e6fb17e0c8c354e6f9`;
- SHA-256 `f0e9628f9e43e3f3476cde06a1849058de460e0e037b7449ce0d42b9a73c37d5`;
- лицензии выбранных 12 файлов перечислены в разделе Apache License
  `third_party/test_fonts/LICENSE` (строки 749–963).

Все 12 TTF закреплены по SHA-256 в `font-bundle-lock.json`; Apache License и
NOTICE находятся рядом в `desktop/assets/isolated-fonts`. Конфигурация
electron-builder копирует комплект вне asar в resources/isolated-fonts.
Клиент проверяет размер и SHA-256 перед передачей файлов нативному API.
Повреждение комплекта, отсутствие API или отказ установки останавливают запуск.

Настройка `fontIsolation` сохраняется в fingerprint; по умолчанию false, в том
числе у старых профилей. Генерация нового отпечатка сохраняет выбранный режим.
Редактор включает переключатель только при подтверждённой поддержке движка.
Контроллер запуска панели также проверяет поддержку, иначе освобождает lease,
не передавая cookies старому клиенту. Это защита актуальной панели, не
универсальный серверный запрет для сторонних/устаревших API-клиентов.

Политика живёт до завершения процесса: для смены режима необходимо
перезапустить Umbra. Старое исключение сайта не отменяет изоляцию.
Для 0.4.32 source-lock закрепляет screen5. CI скачивает архив, проверяет SHA-256
и запускает font fixture до сборки. Проверка установщика требует нативный API,
все 12 шрифтов с правильными SHA-256, LICENSE/NOTICE и совпадающий манифест в
app.asar. Выпуск сначала создаётся черновиком; автообновление становится
доступно после загрузки установщика, blockmap и latest.yml.

## Проверка

```powershell
node desktop/engine/run-fonts-native.cjs D:/umbra-engine/src/out/UmbraTesting/electron.exe "$PWD/desktop/assets/isolated-fonts"
```

Тест работает только на loopback, с временными сессиями, sandbox включён.
Проверяет две изолированные и одну обычную сессию, DOM/Canvas, CSS `local()`,
настоящий OOPIF, dedicated/shared/service workers, загружаемые web-fonts,
неизменяемость политики и недопустимость смены режима после запуска.
На локальной тестовой сборке 30 сентября 2026 проверки прошли дважды на одном
каталоге сессий (два полных запуска). Дополнительно проверены начертания и
fallback-символы, неизменность обычной сессии, запрет поддельного аргумента
изолированного режима. Независимые экранный и CPU/RAM fixtures тоже прошли
два запуска; аудит Canvas/Audio/GPU прошёл в аппаратном и исследовательском
программном режимах. Это не тест нескольких реальных машин.

В процессе тестирования обнаружена ошибка fixture: HTML без charset
декодировал кириллицу иначе, чем worker. HTTP-ответы теперь явно UTF-8;
критерии точного совпадения метрик не ослаблены.

После интеграции: 139/139 desktop-тестов на новом движке с обязательными
native/DPAPI проверками, 198/198 unit-тестов панели/сервера, 2/2 component-only
UI-проверки переключателя (desktop/mobile). Общий старый visual fixture панели
блокируется server-only импортом в мок-окружении; полный UI-regression не
заявляется. Для новой настройки используется отдельный fixture без auth/БД.

## Критерии выпуска

1. Нативная сборка и проверка шрифтов проходят; обычный режим не изменился.
2. Generic-семейства одинаковы в страницах и workers.
3. Отсутствующий/повреждённый комплект останавливает запуск режима изоляции.
4. Экран/CPU/RAM/сеть и разрешённые Canvas/Audio/GPU не регрессировали.
5. Комплект с лицензиями упакован и проверяется; есть явный opt-in в профиле.
6. Ограничения покрытия символов, печати/PDF и аппаратной растеризации указаны
   пользователю; утверждений о неотличимости от Windows-профиля нет.
