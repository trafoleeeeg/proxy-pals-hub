# Расширения по ссылке и закладки профиля

## Что появится у тебя

1. **Добавление расширения ссылкой.** В разделе «Приложение» рядом с кнопкой выбора папки появится поле «Вставьте ссылку». Туда можно вставить:
   - ссылку на страницу расширения в магазине Chrome (`chromewebstore.google.com/detail/...` или старый `chrome.google.com/webstore/...`);
   - прямую ссылку на файл расширения (`.crx` или `.zip`) с сайта провайдера — например, страница загрузки fbacc.
   Клиент сам скачает расширение, распакует, проверит и добавит в список. В списке будут имя, версия и откуда оно взято.

2. **Обновление расширения.** У каждого расширения, добавленного ссылкой, появится кнопка «Обновить» — заново скачает последнюю версию по той же ссылке.

3. **Закладки профиля.** У профиля появится своя панель закладок: в режиме редактирования можно добавить название и ссылку (например, кабинет fbacc). При запуске профиля эти закладки видны сверху в окне профиля и открываются в один клик.

## Ограничения, о которых стоит знать

- Магазин Chrome отдаёт файл расширения только по внутреннему адресу обновлений Google. Некоторые расширения магазин отдаёт с ограничениями — если скачать не выйдет, покажем понятную ошибку и предложим вариант «папкой».
- Расширения, требующие подписи магазина (платные, с привязкой к аккаунту Google), могут не работать вне магазина — это ограничение Chromium, не панели.

## Техническая часть

### Клиент (desktop/)
- `desktop/extensions.cjs`: добавить `addFromUrl(url)`:
  - разбор ссылки: web store → извлечь 32-символьный id → скачать `https://clients2.google.com/service/update2/crx?response=redirect&acceptformat=crx2,crx3&prodversion=<chromeMajor>&x=id%3D<id>%26uc`;
  - прямая ссылка: только `https:`, лимит 200 МБ, таймаут, запрет редиректов на не-https;
  - распаковка: снять CRX2/CRX3 заголовок (magic `Cr24`, версия, длина header), дальше это ZIP; распаковать через встроенный минимальный unzip-модуль (`yauzl`-подобный, либо добавить зависимость `adm-zip`/`yauzl` в `desktop/package.json`) с защитой от zip-slip и символических ссылок;
  - валидация `manifest.json` тем же кодом, что уже используется, затем повторно использовать существующую логику установки (выделить общую `installFromTree`);
  - в реестр писать `source: { type: "store" | "url", url, extensionId }` для кнопки «Обновить».
- `desktop/main.cjs`: IPC `umbra:extensions-add-url`, `umbra:extensions-update` с валидацией входа и вызовом `refreshExtensions()`; лимит одновременных загрузок.
- `desktop/preload.cjs`: методы `addExtensionFromUrl(url)`, `updateExtension(id)`; политика в `desktop/ipc-policy.cjs`.
- Закладки: `desktop/launcher.cjs` передаёт в окно профиля список закладок, `desktop/fingerprint-preload.cjs` не трогаем — панель закладок рисуется в отдельном верхнем `BrowserView`/полоске окна профиля, переключение вкладок по клику.

### Панель (src/)
- `src/lib/desktop.ts`: обёртки новых IPC.
- `src/routes/_authenticated/app.desktop.tsx`: поле ввода ссылки, кнопки «Добавить», «Обновить», статусы и ошибки на русском.
- Закладки профиля: новая миграция — таблица `profile_bookmarks` (`id`, `profile_id`, `title`, `url`, `position`, даты), `GRANT` → `ENABLE RLS` → политики по образцу `profile_access` (владелец команды всё, участник с доступом — чтение). Серверные функции в `src/lib/profile-bookmarks.functions.ts` под `requireSupabaseAuth`. Редактирование — в режиме «Редактировать» на странице профилей; список передаётся в клиент при запуске профиля.

### Проверки
- `bunx tsgo --noEmit`, `node --check` по изменённым `.cjs`, `bun test tests/`, новые тесты на разбор ссылки магазина, снятие CRX-заголовка и защиту от zip-slip.
