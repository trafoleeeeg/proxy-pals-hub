# Перенос публичных настроек Windows из Octo

В создании и редактировании профиля Windows доступен помощник «Перенос настроек
из Octo · Windows». Новая компиляция Chromium для него не нужна. Это не импорт
архива `.octo`, не эмуляция GPU и не гарантия незаметного перехода для сайта.

## Первый профиль: TG CHANNEL

1. Сохранить исходный профиль в Octo. Не удалять его после экспорта.
2. В Umbra создать отдельный пробный профиль; открыть помощник и нажать
   «Образец TG CHANNEL». По предоставленным скринам установлены Windows 11,
   экран 1600×900 и 12 логических потоков. 32 ГБ физической RAM, RTX 4060,
   154 шрифта, режимы «от IP» и выключенные флаги шума — справочные данные,
   не воспроизводимые аппаратные характеристики.
3. Для фактических языка, пояса, сообщаемой памяти и UA выполнить показанный
   код проверки в консоли **исходного Windows-профиля Octo** на тестовой странице
   HTTPS. Код читает только публичные браузерные API, не cookies и не хранилища.
   Вставить результат в помощник; добавить `"osVersion": "11"` по скрину.
   Ничего не выполнять в консоли страницы управления Umbra вместо Octo.
4. Проверить весь отчёт. Если `deviceMemory` равен 16/32, текущее ядро Umbra
   его не воспроизводит: помощник сохраняет выбранные 2/4/8 и явно предупреждает,
   что совпадения нет. Не выдавать физическую RAM в настройках за результат API.
5. Подтвердить ограничения и применить поддерживаемые настройки к форме.
   Политика WebRTC, агрессивная защита, изоляция шрифтов, DNT и стартовый адрес
   не меняются. Сохранение профиля выполняется обычной кнопкой с прежними
   проверками прав и блокировок.
6. Назначить ранее использованный прокси отдельно через интерфейс. Помощник
   не принимает учётные данные и не запускает смену IP.
7. Экспортировать cookies из Octo в JSON; импортировать отдельным штатным полем
   Umbra в закрытый пробный профиль. Не отправлять cookies в чат/диагностику/Git.
   Импорт CHIPS пока не поддерживается и завершается отказом без потери старых данных.
8. Проверить число реально установленных cookies и работу собственной сессии.
   Local Storage, IndexedDB, Service Workers, пароли и device-bound ключи этим
   способом не переносятся. При необходимости выполнить обычный повторный вход.
   Для Telegram Web одного файла cookies может оказаться недостаточно.

Другие два профиля переносить отдельно после проверки первого. Значения
TG CHANNEL нельзя автоматически применять к ним: их исходные настройки неизвестны.

## Формат данных

Помощник принимает только собственный JSON `format: "umbra-settings-v1"`,
Windows, публичные поля (максимум 16 КиБ). Неизвестные поля, cookies, proxy,
password/token, неправильные значения и другие ОС отклоняются. Предпросмотр
локальный: файл не загружается на сервер. Сохраняются только поддерживаемые
параметры отпечатка после обычного сохранения профиля. Справочные поля источника
не сохраняются в базе и не публикуются.

User-Agent источника не применяется: при запуске Umbra версия UA/Client Hints
согласуется с собственным установленным движком, а не с чужим номером Chrome.
Список `languages` сохраняет порядок после канонизации; режим `"ip"` не выбирает
язык или пояс автоматически и не подставляет страну/старую геолокацию прокси.
Все остальные неподдерживаемые поля сопровождаются предупреждениями.

## Проверки

- `bun test tests/profile-migration.test.ts`
- `bun run typecheck` и `bun run build`
- Изолированные desktop/mobile UI fixtures:
  `profile-migration.pw.ts`, `panel-startup-layout.pw.ts`.
  Это не проверка реального аккаунта и не тест на отсутствие обнаружения соцсетями.
