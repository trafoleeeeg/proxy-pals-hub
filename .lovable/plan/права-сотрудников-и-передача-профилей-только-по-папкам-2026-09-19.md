# Права сотрудников и передача профилей только по папкам

## Что меняем в логике

1. **Убираем передачу профиля лично сотруднику.**
   Профилями делимся только через папки. Кнопка «Передать» и «Доступ» на списке
   профилей теряют выбор сотрудника — остаётся только «Перенести в папку».
2. **Пустое пространство у сотрудника.**
   Сотрудник видит только профили из папок, к которым ему выдан доступ. Папка
   «Основная» перестаёт быть автоматически общей — доступ к ней тоже выдаётся вручную.
3. **Панель прав сотрудника.** В разделе «Команда» → «Сотрудники» у каждого
   появляется кнопка «Права». Владелец включает/выключает набор разрешений:
   - создавать профили
   - изменять профиль (имя, заметки, отпечаток, теги, статус)
   - удалять профили
   - менять прокси у профиля
   - создавать/переименовывать/удалять папки
   - управлять прокси команды (добавлять/менять/удалять)
   - управлять закладками команды по умолчанию
   Владелец команды всегда имеет все права, менять их у себя нельзя.
   Запуск профилей и работа внутри браузера (закладки, масштаб, расширения,
   cookies) остаются доступны всем, у кого есть доступ к папке.

## Как это выглядит в панели

- **Список профилей.** Кнопка «Передать» превращается в «В папку» (уже есть),
  «Доступ» убирается. У сотрудника без прав на действие соответствующие кнопки
  скрыты, а не выдают ошибку.
- **Команда → Сотрудники.** Рядом с каждым сотрудником — «Права» (открывает
  окно с переключателями) и «Папки» (список папок с галочками, как сейчас во
  вкладке «Папки», но привязанные к конкретному сотруднику).
- **Вкладка «Папки»** остаётся для управления самими папками.

## Технические детали

- Новая таблица `public.member_permissions(team_id, user_id, permissions jsonb)`
  с булевыми флагами. Владелец (`teams.owner_id`) — все `true` без записи.
  RLS: читают участники команды, пишет только owner.
- Новая security-definer функция `private.has_permission(_user_id, _team_id, _perm text)`.
  Возвращает `true`, если пользователь owner, иначе значение флага.
- Обновляем существующие RPC/серверные функции (`profiles.functions.ts`,
  `folders.functions.ts`, `proxies.functions.ts`, `bookmark-defaults.functions.ts`,
  `bulk_mutate_profiles`, `transfer_profiles`) — заменяем `requireTeamManager`
  на конкретную проверку `has_permission` для соответствующего действия.
  Доступ к профилю по-прежнему проверяется через папку (`folder_access`).
- В `transfer_profiles` убираем параметр `_user_id` (только папка).
- Убираем таблицу `profile_access` и RPC `set_profiles_access` из UI и серверного
  кода (саму таблицу оставляем в базе, чтобы не ломать историю миграций и
  существующие записи — они просто перестают влиять, потому что доступ теперь
  считается только по `folder_access`).
- В `useWorkspace` и `list*`-серверных функциях фильтруем видимые команды/папки/
  профили: не-owner видит только те папки, что есть в `folder_access`, и только
  профили внутри этих папок.
- Новый серверный `getMemberPermissions(teamId, userId)` и
  `setMemberPermissions(teamId, userId, permissions)` — owner-only.
- Клиентский хук `usePermissions()` — возвращает объект флагов текущего
  пользователя в активной команде, чтобы скрывать кнопки в UI.

## Что НЕ меняем

- Шифрование cookies и паролей прокси, RLS модель (только расширяем), схему
  синхронизации, версию клиента, миграции прошлых версий, авторизацию.

## План выпуска

Собирать новую версию клиента не требуется — все изменения в панели и в облаке.
После утверждения плана применю миграцию, обновлю серверные функции и UI,
прогоню `bunx tsgo --noEmit` и тесты, проверю Playwright'ом вход и меню прав.
