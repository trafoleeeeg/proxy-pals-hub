# Umbra 0.4.59 — восстановление панели после простоя

Исправлены подтверждённые дефекты порядка восстановления панели:

- Событие пробуждения и разрыв интервала таймера сами объявляли потерю связи,
  даже если сервер был доступен. Теперь сон не считается сетевой ошибкой.
- Запросы по focus/reconnect, включая отдельный принудительный запрос прав,
  выполнялись одновременно с проверкой авторизации. Теперь один координатор
  сначала проверяет сессию, затем обновляет маршруты, команду и активные запросы.
- Сетевой отказ после пробуждения мог ждать следующего 15-секундного тика.
  Теперь повторные проверки начинаются через 250 мс, далее используют
  ограниченный backoff 750/1500/3000/5000/15000 мс без параллельного накопления.
- При кратком сетевом отказе ранее загруженные таблицы остаются на экране,
  без дублирующих ошибок прав, профилей, прокси и команд. Одна общая плашка
  появляется, если реальная потеря связи сохраняется дольше трёх секунд.

Просмотр ранее загруженного состояния не предоставляет новые права:
при ошибке запроса прав изменяющие действия не разрешаются по старому кэшу,
а серверные проверки авторизации и RLS остаются обязательными.
Истёкшая сессия и ошибки доступа не маскируются как сетевой сбой.
Автоматическое восстановление не повторяет mutations, не возобновляет
отложенные записи и не переключает браузерный online-флаг принудительно.

Новые тесты воспроизводят многодневный разрыв таймера, native resume,
одновременные focus/online/visibility события, временную недоступность,
ограничение повторов, порядок auth → workspace → queries и отмену наблюдения.
Локально на Windows прошли 322 теста панели и проверка типов.
Сборка и полный Windows-прогон клиента обязательны в GitHub до публикации.

Точная причина исторического отказа сервера/сети на скриншоте в локальном
журнале не записана. Этот выпуск исправляет воспроизведённые дефекты
восстановления; он не обещает мгновенного доступа при реальном отсутствии
интернета или недоступности сервера.

Движок, база и реальные cookies не меняются. Рабочее приложение
и профили принудительно не закрываются.
