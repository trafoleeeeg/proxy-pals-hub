# Регулярные обновления движка Umbra

Umbra использует собственную сборку Electron/Chromium с нативными патчами.
Обновление npm-пакета `electron` само по себе **не обновляет** движок, который
попадает в Windows-приложение. Поэтому автоматический выпуск только после
обновления зависимости запрещён.

## Ежедневная проверка

Workflow `Engine update watch` запускается ежедневно в 05:23 UTC и вручную
через `workflow_dispatch`. Он сравнивает `desktop/engine/source-lock.json`
с последним стабильным Electron из npm и стабильным Chrome for Testing.
Когда появляется более новая версия, workflow создаёт или обновляет одну
задачу GitHub с чек-листом портирования и проверки. Он не меняет код,
не собирает движок и не публикует клиент. При ошибке проверки workflow падает,
чтобы отсутствие данных не принималось за актуальность движка.
Задача закрывается вручную после выпуска: совпадение версий ещё не доказывает,
что установщик и автообновление проверены.

Отдельно проверяйте [поддерживаемые ветки Electron](https://www.electronjs.org/docs/latest/tutorial/electron-timelines)
и срочные исправления безопасности. Новый Chrome может появиться раньше
совместимой стабильной версии Electron; это сигнал для оценки, а не указание
самостоятельно подменять Chromium в готовом ZIP.

## Обновление

1. Создать отдельную ветку из актуального `main` и выбрать стабильную версию
   Electron, включая фактически встроенные Chromium и Node.js.
2. Перенести патчи в `desktop/engine/`, собрать новый Windows-движок и
   запустить нативные тесты screen, hardware, fonts, DNS и network.
3. Опубликовать *тестовый* архив движка и закрепить исходные коммиты, тег
   архива и SHA-256 в `desktop/engine/source-lock.json`.
4. В том же PR обновить `desktop/package.json` и lockfile. Запустить CI:
   он сверит npm-версию с source-lock, SHA скачанного архива и версии
   Electron/Chromium/Node, которые сообщает распакованный `electron.exe`.
5. После зелёного CI проверить установщик и обновление клиента. Только затем
   разрешить отдельный релиз приложения. При провале вернуть PR на доработку;
   старый клиент остаётся рабочим.

Проверка на локальном распакованном архиве:

```powershell
node desktop/scripts/verify-engine-runtime.cjs D:\path\to\electron.exe
```

Архив `desktop/.engine/dist.zip` на рабочем компьютере может быть устаревшим.
Его нельзя переиспользовать для релиза без проверки SHA из source-lock.
