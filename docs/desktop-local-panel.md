# Локальная панель Umbra

Панель поставляется внутри установщика: root-only SPA-документ TanStack и
хешированные публичные JS/CSS. Это не снимок аккаунта и не офлайн-копия базы.
У сайта сохраняется SSR; `/_umbra-panel.html` генерируется отдельно без
авторизованного маршрута. Внешние шрифты панели больше не загружаются.

## Запуск и доступ

- Только `persist:umbra-app` обслуживает локальные ресурсы под прежним HTTPS
  origin. Профильные сессии не перехватываются. Sandbox, context isolation,
  запреты разрешений и проверки IPC не ослаблены.
- Первый локальный документ показывается, не ожидая сетевой гидратации.
  Пока `getUser()` не подтвердит сессию, видны лишь публичные элементы оболочки;
  профили, названия папок, email и действия с данными не монтируются.
- Проверки пользователя и рабочих пространств запускаются параллельно. Результат
  команд попадает только в память и только после подтверждения совпадающего
  пользователя. Селектор команды и текущая команда используют один запрос.
- POST, server functions, Supabase auth и другие API идут на сервер. Cookies,
  пароли, профили, токены, права и ответы API не входят в кэш интерфейса.

## Обновление

Сборка публикует `umbra-panel.json` с размерами, SHA-256, датой сборки и минимальной
версией клиента. Через 15 секунд после старта клиент проверяет его по HTTPS,
без credentials, редиректов и без блокировки первой отрисовки. Ограничения:
256 файлов, 20 МиБ суммарно, четыре одновременные загрузки, 60 секунд на попытку.
Разрешены только перечисленные публичные ресурсы, не произвольные пути.

Полная новая генерация проверяется до активации. Её манифест/указатель защищены
`safeStorage` (DPAPI на Windows) и заменяются атомарно. Новая версия применяется
только в следующем процессе: reload, навигация, employee preview и открытые
профили не переключают набор JS в середине сессии. При повреждении/недокачке
используется проверенная сборка установщика; при недоступном OS encryption
фоновые обновления кэша отключены. Если повреждена сама сборка установщика,
остаётся прежний безопасный сетевой запуск.

Стабильные имена server functions и обратная совместимость RPC нужны между
выпусками, как для любого установленного клиента. Изменение контракта требует
нового desktop-выпуска/минимальной версии, а не удаления старого RPC сразу.
HTTPS и DPAPI не являются защитой от уже захваченного аккаунта ОС или сервера.

## Проверки

`bun run build` создаёт и проверяет `desktop/.panel`; Windows CI включает его
в ASAR и проверяет каждый ресурс внутри готового установщика. Unit-тесты:
целостность, traversal, ограничения размера, rollback, требуемая версия,
передача POST на сервер, прерванное обновление, применение после рестарта.
Нативный изолированный тест: SPA при полностью отключённой сети, сохранение
HTTPS origin/IPC/sandbox, переход на вход и другой раздел, а также задержанная
проверка синтетической сессии без показа её identity и без удержания overlay.

Скорость локального документа не равна скорости холодного запуска Electron
или загрузки данных аккаунта. Сетевая проверка прав остаётся обязательной.

Локальный прогон: 252 модульных проверки, 14 проверок startup/cache, нативный
Windows-тест с настоящей DPAPI и два новых desktop/mobile UI-сценария прошли.
В нативных прогонах документ загружался за 0,44–0,97 с; это не SLA холодного
старта. Старый полный visual-набор: 4/30 прошли, 26 упали; среди устаревших
ожиданий — поиск профиля из «Работы» при выбранной «Основной», прежние сообщения
обновлений/расширений и удалённая точечная выдача прав. Его полная актуализация
не входит в это изменение; зелёным полный visual-набор не считается.
