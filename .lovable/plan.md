# Свой антидетект: как это устроить

## Архитектура

Рабочее место команды — отдельная программа для Windows и macOS. В обычном
браузере ничего открывать не нужно: это и безопаснее, и иначе профили просто не
запустить.

```text
[ Десктоп-клиент Windows / macOS ]  <-->  [ Серверная часть (собираем здесь) ]
  вход сотрудника, список профилей          база профилей, отпечатков, прокси
  запуск браузера с отпечатком и прокси     доступы, команда, журнал действий
  локальное хранение cookies                выдача данных строго по правам
```

Сервер не является сайтом для работы — это закрытое хранилище и API. Никакого
входа в профили через обычный браузер, никакого пересечения с личными данными
основного браузера: клиент запускает свой изолированный Chromium со своим
каталогом данных.

Подмена отпечатка (Canvas, WebGL, шрифты, аудио, WebRTC, часовой пояс) возможна
только внутри самого браузера на компьютере — поэтому она живёт в клиенте.

## Что умеет система

**Профили**
- Список профилей: название, теги, папки, заметки, статус (свободен / занят / у кого).
- Карточка профиля: отпечаток под Windows — версия Chrome, разрешение экрана,
  видеокарта (WebGL), язык, часовой пояс, число ядер, объём памяти, шрифты.
- Генерация случайного, но правдоподобного набора (не «мусорные» комбинации:
  часовой пояс и язык подбираются под страну прокси).
- Клонирование профиля, массовое создание, импорт/экспорт списком.
- Хранение cookies и данных сессии профиля в зашифрованном виде.

**Прокси**
- Добавление вручную и списком: `host:port:login:pass`, типы HTTP/SOCKS5.
- Кнопка «Проверить»: реальный IP, страна, город, задержка, статус.
- Привязка прокси к профилю, предупреждение, если один прокси на нескольких
  профилях.
- Пароли прокси зашифрованы и не показываются сотрудникам открыто.

**Команда**
- Владелец приглашает сотрудников по email.
- Сотрудник видит только те профили, которые ему выдали. Больше — ничего.
- Владелец может забрать доступ в один клик, сессии сотрудника при этом рвутся.
- Журнал действий: кто, когда, какой профиль открыл, что изменил.

**Безопасность**
- Вход по email + паролю, обязательная двухфакторная аутентификация для владельца.
- Проверка пароля по базе утечек.
- Cookies, пароли прокси и данные профиля шифруются; в базе лежат нечитаемыми.
- Доступ к данным проверяется на сервере, а не в интерфейсе — подменить нельзя.
- Блокировка одновременного открытия одного профиля двумя людьми.

## Десктоп-клиент (Windows и macOS)

Одно приложение на Electron, собирается под обе системы из одного кода.

- Вход сотрудника по email и паролю + 2FA, сессия хранится в системном
  хранилище ключей (Keychain на macOS, DPAPI на Windows), а не в файле.
- Список только тех профилей, к которым есть доступ.
- Кнопка «Запустить»: клиент берёт с сервера отпечаток и прокси, расшифровывает
  cookies в памяти и стартует изолированный Chromium с отдельным каталогом
  данных. К основному браузеру пользователя он не имеет отношения.
- При закрытии cookies шифруются на устройстве и уходят обратно на сервер.
- Профиль блокируется на время работы, чтобы двое не открыли его одновременно.
- Автообновление клиента и подпись сборки.

Сборку под Windows и macOS я подготовлю; подписывать macOS-версию сертификатом
разработчика и, при необходимости, EXE-подписью нужно будет вам.

Честно о сложности: качественная подмена отпечатков — это месяцы работы и патчи
в исходники Chromium. Разумно опереться на готовую открытую основу: Camoufox
(на базе Firefox) или undetected-chromedriver. С нуля писать движок смысла нет.

Сначала делаем серверную часть и минимальный клиент, который умеет входить,
показывать профили и запускать браузер с базовым отпечатком. Дальше углубляем
подмену отпечатков.

## Масштаб

20 профилей и небольшая команда — это лёгкая нагрузка, всё уместится в базовый
бесплатный уровень. Архитектура сразу рассчитана на рост до тысяч профилей.

## Экраны клиента

1. Вход / двухфакторная.
2. Профили — таблица с фильтрами, папками, массовыми действиями, кнопка запуска.
3. Карточка профиля — отпечаток, прокси, заметки, история.
4. Прокси — список, проверка, привязки.
5. Команда — приглашения, выдача доступа к профилям, журнал действий
   (видит только владелец).
6. Настройки аккаунта — пароль, 2FA, устройства.

Регистрация владельца и приглашения сотрудников — минимальная веб-страница
(только это и страница скачивания клиента), всё остальное только в программе.

## Техническая часть

Backend — Lovable Cloud (Postgres + auth + серверные функции).

Таблицы: `profiles_browser`, `fingerprints`, `proxies`, `profile_access`,
`team_members`, `audit_log`, `profile_locks`, `user_roles`.

- Роли хранятся в отдельной таблице `user_roles` с функцией `has_role`,
  никогда в профиле пользователя.
- RLS на всех таблицах: сотрудник видит строку, только если есть запись в
  `profile_access` на его `auth.uid()`.
- GRANT-ы для `authenticated` и `service_role` в той же миграции.
- Секреты (пароль прокси, cookies) шифруются через `pgcrypto` ключом из секрета
  проекта; расшифровка только в серверной функции после проверки доступа.
- Проверка прокси — серверная функция (`createServerFn`), запрос через прокси
  к сервису определения IP; из браузера напрямую нельзя.
- Блокировка профиля — строка в `profile_locks` с TTL и heartbeat от локальной
  программы.
- Аудит — триггеры на изменение + явная запись при открытии профиля.

Клиент — Electron, интерфейс на том же React-коде, сборка под Windows (.exe) и
macOS (.zip/.dmg). Запуск браузера — отдельный изолированный Chromium с
`--user-data-dir` на профиль и прокси через флаги, авторизация прокси — через
локальный перехват. Токен доступа в системном хранилище ключей, не в файле.

## Порядок работы

1. Lovable Cloud: схема БД, RLS, шифрование.
2. Регистрация владельца, вход, 2FA, роли владелец/сотрудник.
3. Профили: CRUD, генератор отпечатков Windows, папки, теги.
4. Прокси: импорт, проверка, привязка.
5. Команда: приглашения, выдача доступа, журнал действий.
6. API синхронизации и блокировок для клиента.
7. Сборка Electron-клиента под Windows и macOS, запуск браузера с отпечатком.
8. Углубление подмены отпечатков на открытой основе.
