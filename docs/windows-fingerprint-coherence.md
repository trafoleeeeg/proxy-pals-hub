# Согласование отпечатка Windows с прокси: первый этап

После успешной проверки выходного IP настольный клиент делает необязательный
HTTPS-запрос к `ipapi.co` **через ту же временную прокси-сессию**. Сервис видит
выходной IP прокси, но не получает cookies профиля или учётные данные прокси.
Ответ принимается только при совпадении IP с результатом проверки соединения.
Если геосервис недоступен или вернул неподтверждённый ответ, проверка прокси
остаётся успешной, а часовой пояс считается неизвестным.

Подтверждённый пояс сохраняется вместе с последним проверенным IP. При смене IP
старый пояс очищается. Для нового профиля выбор уже проверенного прокси задаёт
этот пояс автоматически. У существующего профиля несовпадение показывается в
редакторе с кнопкой явного применения: без действия владельца его отпечаток
не меняется. Геолокация IP может ошибаться, а смена пояса действующего профиля
может повлиять на сессию сайта.

Это не эмуляция GPU, Canvas, аудио или сетевого TCP-стека. Обычный режим
Electron по-прежнему может раскрывать реальное оборудование машины; строгий
режим блокирует часть API и этим отличается от обычного Chrome. Пассивный
TCP-отпечаток мобильного прокси формируется на стороне прокси и не исправляется
JavaScript-подменой в клиенте. Гарантии нераспознаваемости здесь нет.

Миграция `20260929100000_proxy_geo_timezone.sql` добавляет только необязательное
поле. До её применения список прокси и проверка соединения используют прежнюю
схему, поэтому панель остаётся работоспособной; определённый пояс при этом
ещё не сохраняется между загрузками.
